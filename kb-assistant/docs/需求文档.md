# kb-assistant 需求文档（课程助教）

> 版本：v0.1 草案 ｜ 日期：2026-11-13 ｜ 状态：待确认
> 一句话定位：把六周课程学到的 RAG/Agent 技术，装进一个**自己天天会用**的课程助教里——边做项目边学，每个新学的能力都作为组件装进来，并用评测闭环验证它有没有用。

## 一、项目背景与目标

**背景**：学员正在按 6 周计划学习 LLM/RAG（Day 0-18 已完成：模型调用基本功、RAG 第一条链路、切片优化、混合检索）。学习中产生了大量自有材料：学习计划、教学笔记、Bad Case 台账。这些材料的问答需求目前靠人工翻找。

**目标**：做一个课程助教，学员用自然语言提问，助教基于课程语料给出**带来源引用**的回答；答得好不好**用数据说话**（评测闭环），而不是感觉。

**三个候选方向（内部文档问答 / 课程助教 / 技术债分析助手）共享同一工程内核**，本项目先做课程助教，内核稳定后其余两个方向作为新配置接入（换语料 + 换 system prompt + 换工具）。

## 二、用户与场景

| 用户 | 场景 | 交互方式 |
|---|---|---|
| 学员本人（唯一用户） | "第六周学什么？""Day 16 修了什么？""术语 X 是什么意思？" | v0.1 命令行 → v0.5 起网页工作台 |

## 三、范围界定

**v0.1 包含（MVP）**：
1. 知识库构建：课程语料的清洗、结构感知切分、向量化、ChromaDB 入库
2. 混合检索：BM25 + 向量双路，RRF 融合（Day 18 成果迁移）
3. RAG 问答：检索 → 拼 Prompt → 生成带 [n] 引用的回答；拒答与推断平衡（Day 12/16 成果）
4. CLI 交互入口

**明确不在 v0.1（后续版本装）**：
- Function Calling / 工具调用 → v0.6（第 6 周 Agent 阶段）
- 流式输出 / FastAPI 工作台 → v0.5（第 5 周）
- 自动评测脚本 → v0.4（第 4 周）
- 多轮对话 / 查询改写 → v0.3（Day 20）

## 四、功能需求

### FR-1 知识库构建（已实现，随 v0.1 迁移）
- FR-1.1 语料接入：`corpus/` 目录下的 .md 文件（学习计划、MISSION/NOTES/RESOURCES、Bad Case 台账）
- FR-1.2 清洗：剥离 Markdown 头部元信息块（title/keywords/tags）
- FR-1.3 切片：按标题层级结构感知切分，小节超 500 字用固定长度+重叠兜底，每片带标题路径前缀
- FR-1.4 向量化：BAAI/bge-small-zh-v1.5（512 维，本地离线）
- FR-1.5 入库：ChromaDB 持久化，cosine 空间；支持多集合并存（新旧切片对比）

### FR-2 检索（已实现，随 v0.1 迁移）
- FR-2.1 双路召回：向量（语义）+ BM25/jieba（字面），各自 top-20
- FR-2.2 RRF 融合（K=60）成候选池
- FR-2.3 Rerank 精排：bge-reranker-base 对候选池打分，取 top-5 进 Context（**待 v0.2 接入**，模型下载中）

### FR-3 问答（已实现，随 v0.1 迁移）
- FR-3.1 课程助教人设的 system prompt（四条规则：只依据资料 / 标 [n] 引用 / 不足拒答 / 有原理允许一步推断）
- FR-3.2 回答必须可溯源：[n] 能映射到 corpus/ 里的具体文件
- FR-3.3 复用 chat.py 地基：超时、重试、Token 统计
- FR-3.4 （v0.3）多轮对话：上下文里的"它怎么部署？"要能改写成完整问题再检索

### FR-4 评测闭环（v0.4 新建，本项目区别于练手 Demo 的核心）
- FR-4.1 评测集：30-50 条「问题 + 标准答案 + 标准出处」，覆盖事实题 / 推理题 / 语料外题
- FR-4.2 检索指标：Recall@5（标准出处是否进 Top-5）
- FR-4.3 生成指标：LLM 当裁判评忠实度、相关性（结构化输出保证 JSON 可解析）
- FR-4.4 每次优化跑同一评测集，指标变化记录进台账（现象→定位→改了什么→效果）

### FR-5 服务化工作台（v0.5）
- FR-5.1 FastAPI：问答接口 + SSE 流式接口
- FR-5.2 会话管理、统一错误处理、Token 成本统计与预算上限
- FR-5.3 压测：P95 / P99 / TTFT，一页容量报告

### FR-6 Agent 能力（v0.6）
- FR-6.1 至少 1 个工具：查学习进度（读学习计划 + 完成状态）
- FR-6.2 ReAct 循环 + 最大步数 + Trace 日志
- FR-6.3 验收：能说清"什么时候该用 Workflow、什么时候才需要 Agent"

## 五、非功能需求

| 项 | 要求 |
|---|---|
| 成本 | DeepSeek API，单问输入 ≤ 1200 token（Rerank 后 context 更聚焦，目标 ≤ 800）；超预算熔断（v0.5） |
| 延迟 | CLI 无硬指标；v0.5 起关注 TTFT |
| 可复现 | 模型全部本地缓存（bge / reranker），离线开关写死在代码顶部；任何一台机器 clone 后按 README 可复跑 |
| 安全 | .env 存 Key 且永不入库；日志不打印 Key |
| 语料边界 | 语料更新后需重跑整条离线链路（切片→编码→入库），在线查询模型与建库模型必须一致 |

## 七、风险与依赖

1. **Cross-Encoder 速度**：CPU 上 20 对 × 512 token 约 10-30 秒/问——v0.2 若太慢，降池子到 10 或换 API rerank；
2. **语料形态**：teach/ 下 lessons 是 HTML，v0.1 不入库；v0.3+ 如需入库要加 HTML→文本解析；
3. **评测集的主观性**：标准答案由学员自己写，v0.4 要引入"让 LLM 先答、人再校对"的流程降低偏置；
4. **Windows 环境坑**：transformers 导入扫描慢（实测 42s）已接受；杀毒软件实时扫描可能拖慢首跑。

## 八、候选优化池（技术储备，非当前承诺）

> 来源：rag_optimization.md / long_document_code_retrieval.md 等阅读材料。
> 进入实施的条件：评测闭环（v0.4）跑出指标后，按"短板 → 对症下药"从池中取用，不做无指标驱动的优化。

| 技术 | 解决什么问题 | 触发条件 | 计划版本 |
|---|---|---|---|
| **父子块检索** | 检索用小块（准）但喂模型上下文不全；命中子块后改喂其父级小节 | 评测显示"答对但引用外上下文残缺/回答不完整"时 | v0.4 后视指标 |
| **Context 压缩** | 召回片段里无关内容多，浪费 Token、稀释注意力 | 单问 Token 超预算（>800）或噪声占比高 | 视评测 |
| **Multi-Query 多角度查询** | 单一问法召回不全 | Recall@5 偏低的同义改写类问题 | v0.3 与查询改写一起评估 |
| **元数据过滤** | 语料多来源时需要限定范围（如"只查学习计划"） | 工作台加筛选功能时（v0.5+） | v0.5 视需求 |
| **AST 切分** | 代码文件按函数/类边界切，函数不腰斩（Markdown 的"按标题切"的代码版） | **接入代码语料时——即"技术债分析助手"方向启动时** | 三方向之二 |
| **HTML→文本解析** | teach/ 下 lessons 课件是 HTML，目前未入语料 | 需要课件内容入知识库时 | v0.3+ 视需求 |
| **Rerank 分数拒答阈值** | ~~用精排分数做硬拒答开关~~ **已否决（2026-11-15）**：8 道语料外题池内最高分 0.003~0.979 无分界（术语表沾边），Prompt 规则仍是拒答主力 | —— | ❌ 已否决 |
