## 二、硬指标点（有实测数字，面试可复现）

- **结构感知切分 + 语料清洗**：目标段落检索排名 12 → 1；Top-5 噪声块占比 40% → 0；单问输入 Token 870 → 755（-13%）。（2026-11-13, Day 16, week2-rag/bad_cases.md 台账）
- **混合检索（BM25+向量，RRF 融合）实测对比**：精确词查询 BM25 第 1 名而向量排第 3（"64 token 例子"）；同义改写查询向量第 1 名而 BM25 前 5 无一命中（"切片大小设多少"）——两路短板互补，RRF 只看名次实现量纲无关融合。（2026-11-13, Day 18）
- **拒答门控**：system 规则"只依据资料/标引用/不足拒答/有原理允许一步推断"——语料外问题（红烧肉）稳定拒答，且放宽推断后回归测试仍守住拒答边界。（2026-11-12/13, Day 12/16）
- **幻觉对抗链条**：检索增强（只喂资料）+ 引用可溯源 + 拒答出口 + 拒答回归测试，四层设计各有验证。（v0.1）

- **多轮对话查询改写（指代消解）**：追问"它怎么部署？"经改写器补全为"Embedding 模型怎么部署？"后，检索命中 Embedding 本地部署/API 方案；对照组证明不改写时 Top-1 是"大模型部署方案"——张冠李戴。改写器跨两轮携带话题（第三问自动补全 BGE/M3E 限定词）。设计：改写进检索不进生成，历史浓缩后单问 Token 不膨胀。（2026-11-14, v0.3, commit 见 git）

- **Rerank 精排（Cross-Encoder）**：64-token 例题的正确小节精排后以 0.98 分断层 Top-1（精排前第 2，次名仅 0.38）；"宽召回 top-20 → 精排 top-K"已接入主链路，RAG_K 环境变量可调。（2026-11-14, v0.2）
- **K 权衡实测**：RAG_K=3 时单问输入 Token 均值 946 vs 纯向量 K=5 基线 1150（-18%），但 800 目标未达，且 K=3 会丢失部分台账片段（BC-3 类问题受影响）——K 的最优值留待 v0.4 评测集决定，这正是"指标驱动优化"的待办。（2026-11-14）
- **新洞察：Rerank 分数可作拒答阈值**：语料外问题（红烧肉）候选池精排分全部 ≈0（最高 0.07），语料内强相关 ≈1.0——分数天然形成拒答开关，比 Prompt 规则更硬。已记入候选优化池待 v0.4 验证。（2026-11-14）

- **评测基线确立（Golden Set 35 条，生产链路 K=5）**：Recall@5 = 96.3%（26/27，fact 94.7%/reasoning 100%）、MRR = 0.880。（2026-11-15, v0.4）
- **评测驱动的两个发现**：①唯一 MISS（F001）坐实"元文档抢排名"——bad_cases.md 字面复述问题原文被 reranker 高分顶位，知识原文被挤出 Top-5，指标损失被量化（→ 修复靶子：入库打元数据降权）；②自提的"Rerank 分数拒答阈值"假设被自己的评测否决——8 道语料外题池内最高分 0.003~0.979 无分界（术语表沾边导致），上线前拦下坏功能。（2026-11-15）

## 三、方法论/软实力（面试讲"怎么想"的素材）

- **Bad Case 本工作流**：现象 → 定位 → 改了什么 → 效果，全案例台账（BC-1 检索侧 / BC-2 生成侧，两类病因两种修法）。（2026-11-13）
- **优化决策纪律**：候选优化池（父子块/Context 压缩/Multi-Query/AST 等 6 项）全部等 v0.4 评测指标触发，拒绝无基线的过早优化；Token 超标先试调 K（便宜手段），不够再上 LLM 压缩（贵手段）。（2026-11-14）
- **离线/在线分离**：改切片 = 全链路重跑的亲身体会；离线在线必须同一 Embedding 模型，否则向量空间失效。
- **三模型分工架构**：bge-small（管找，本地 512 维）/ bge-reranker（管挑，Cross-Encoder）/ DeepSeek（管答，API）——检索侧换模型=全库重编码，生成侧换模型只改 base_url。
- **踩坑记录**：HF 本地模型仍会联网校验导致卡 8 分钟（加 HF_HUB_OFFLINE）；transformers 导入扫描全包文件实测 42s（纯磁盘 I/O）；cp 全量拷 .venv 卡死 6 分钟（改 tar --exclude）。

## 四、优化前后对照（现象 → 改动 → 效果，面试白板题素材）

> 每做一次优化就在这里补一张对照表：改之前什么病、动了哪一刀、前后数据对比。

### 4.1 结构感知切分 + 清洗（2026-11-13, Day 16）

**现象**：问"切片大小一般设多少合适？"，模型答"资料中没有数值"——但语料里明明有经验值。
**改动**：剥离 title/tags 元信息块；按 `##` 标题切分（500 字兜底）；每片拼标题路径。

| 指标 | 改前（固定长度切分） | 改后（结构感知） |
|---|---|---|
| 目标段（经验值段）检索排名 | 第 12 名（相似度 0.442） | **第 1 名** |
| Top-5 中元信息垃圾块 | 2/5（40%） | **0** |
| 单问输入 Token | ~870 | ~755（-13%） |

### 4.2 混合检索 BM25 + 向量（2026-11-13, Day 18）

**现象**：单路检索各有死穴——向量对精确词不敏感，BM25 对同义改写抓瞎。
**改动**：双路各召回 top-20，RRF（K=60）按名次融合。

| 问题类型 | 向量单独 | BM25 单独 | RRF 融合 |
|---|---|---|---|
| 精确词（"64 token 的例子"） | 正确小节排 #3 | **正确小节 #1**（25.7 断层） | 正确答案进 Top-2 |
| 同义改写（"设多少合适"） | **经验值段 #1** | 前 5 无一命中 | 经验值段 #1（守住了） |

### 4.3 查询改写 + 多轮（2026-11-14, v0.3）

**现象**：追问"它怎么部署？"缺主语，不改写直接检索会张冠李戴。
**改动**：改写器读最近 3 轮历史补全主语，改写后的问题进检索（不进生成）。

| | 检索 Top-1 | 后果 |
|---|---|---|
| 不改写 | `deployment_options.md`（大模型部署方案） | 张冠李戴——"它"被当成大模型 |
| 改写后（"Embedding 模型怎么部署？"） | Embedding 本地部署/API 方案 | 指代正确，回答带引用 |

### 4.4 Rerank 精排（2026-11-14, v0.2）

**现象**："64 token 例子"的正确小节（`## 三、Overlap`）在融合榜只排第 2，第 1 是语义沾边但不对的"Chunk 过大过小"。
**改动**：混合宽召回 top-20 → Cross-Encoder（bge-reranker-base）对 20 对 (问题， 片) 精细打分 → 取 top-K（RAG_K 可调）。

| | Top-1 | 次名 |
|---|---|---|
| 精排前（混合） | "Chunk 过大过小"（错的） | Overlap 小节（对的，#2） |
| **精排后** | **Overlap 小节，0.98 断层第一** | 0.38 / 0.31 |

**K 权衡（待 v0.4 裁决）**：RAG_K=3 时 Token 均值 946 vs 基线 1150（-18%），但 800 目标未达，且 K=3 丢失部分台账片段（BC-3 类问题受影响）——K 的最优值交给评测集。

### 4.5 拒答门控（贯穿 v0.1-v0.2）

| 版本 | 手段 | 验证 |
|---|---|---|
| v0.1 | Prompt 规则 3（不足直说） | 红烧肉正确拒答 |
| v0.1/v0.3 | 规则 4（允许一步推断） | BC-2 推理作答，且红烧肉回归仍拒答 |
| v0.2 发现 | Rerank 分数天然分档（语料外全池 ≈0 vs 语料内 ≈1.0） | 候选池新增"分数拒答阈值"，待 v0.4 验证 |

### 4.6 元数据过滤：对话生成的资料不能影响 RAG（2026-11-15, v0.4）

**现象**：评测唯一 MISS（F001"切片大小怎么设"）——bad_cases.md 台账字面复述问题原文，被 reranker 高分顶位，知识原文挤出 Top-5。
**改动**：语料配置打 `kind` 标签（course/log）→ 切片/向量化透传 → Chroma 入库带元数据 → 检索两路过滤（向量路 `where kind!={log}`，BM25 路列表过滤）。日记仍留库中（查修复历史可 `where kind=log`），只是不干扰知识检索。

| 指标 | 过滤前 | 过滤后 |
|---|---|---|
| F001 | MISS（教科书被日记挤出 Top-5） | **HIT@1** |
| Recall@5 | 96.3%（26/27） | **100%**（24/24） |
| MRR | 0.880 | **0.948** |

### 4.7 LLM 裁判的迭代：裁判自己也被评测揪出 bug（2026-11-15, v0.4）

**现象**：裁判 v1（只看问题+标准答案+回答）把"语料里有、标准答案里没有的正确细节"判成编造——F001 的产品手册调参案例（语料原文）被冤枉，R005 的模型价格（语料原文）被判 2/2 fail。
**改动**：裁判输入加入【检索到的资料】，忠实度重定义为"忠于资料"（资料里有但标准答案里没有的正确细节不算编造），正确性继续对标准答案负责。

| | 裁判 v1（无资料） | 裁判 v2（带资料） |
|---|---|---|
| 忠实度均值 | 4.20（误判） | 5.00 |
| F001 | warn（冤案） | pass ✅ |
| R005 | fail 2/2（部分冤枉） | 5/4 pass——公式遗漏由正确性维度如实扣分 ✅ |
| F009/R008 模型拿预训练知识补细节 | 混在误判里 | 忠实度 5（细节可由资料合理推断） |

**已知局限**（诚实记录）：①忠实度满分 5.00 均匀无区分度——LLM 裁判的打分压缩现象，当前信号主要靠正确性维度承载；②裁判本身是概率模型，判断需抽查背书（F001/F009/R005/R008/X004 五条已人工抽查）。拒答率 71.4%（X003 语料沾边诱导编造=Day 26 靶子；X002 系标志词口径已修，按存档答案重算 85.7%）。

### 4.8 错误分析 → 拒答门控优化（2026-11-16, Day 26-27）

**错误盘点（32 题全量）**：检索失败 0 条（Recall@5 100%）、引用缺失 0 条、生成漏答 5 处（均为"轻微遗漏要点"，correctness=4，无错误回答）、**拒答漏网 2 条（28.6%）= 最大短板**（X002 示例句污染：文章拿"今天天气"当调用例子；X003 术语沾边）。
**改动**：规则 3 加"什么算资料不足"的判据——关键词出现/概念定义/示例顺带提及都不算直接回答问题；规则 4 收边界——推断只能沿资料原理走一步，不能扩展成方法论/选型建议。
**效果**：
| 指标 | 优化前 | 优化后 |
|---|---|---|
| 拒答率 | 5/7（71.4%） | **6/6（100%）**※ |
| 生成 pass | 25/25 | **25/25（无退化）** |
| 正确性 | 4.84 | 4.80（5 处轻微遗漏，非错误） |
※ X003 经查为**评测集过时标注**（llm_keywords.md 第243行有「知道新知识→RAG；学会新能力→微调」原句，模型引用正确）——第三次"评测集跟着语料走"的平反，改判为 fact 题。X002 由新判据真实修复。
